All editable content lives in `data/` as plain TypeScript files. There's no CMS — just edit the file and the page updates automatically.

## Team Members (`data/team.ts`)

```ts
export type TeamMember = {
  name: string;
  role: string;
  image?: string; // relative path to image in /public
};

export const teamMembers: TeamMember[] = [
  { name: 'Your Name', role: 'President' },
  { name: 'Name Two',  role: 'VP Finance & Administration' },
  // ...
];
```

**Current roles (in order):**
1. President
2. VP Finance & Administration
3. VP Media
4. VP External
5. Electrical Lead
6. Mechanical Lead
7. Software Lead

The home page's "Where you fit" cards show the lead for each team by looking up the role (`Software Lead`, `Electrical Lead`, `Mechanical Lead`, `VP Media`), so keep those role names as they are.

### Adding a photo

1. Drop the photo into `public/team/` (create the folder if it doesn't exist). Square or portrait crops work best — the card uses `aspect-[3/4]`.
2. Add the path to the member's `image` field:

```ts
{ name: 'Jane Smith', role: 'President', image: '/team/jane.jpg' }
```

3. Update the team card in `app/team/page.tsx` to render the image using `next/image`:

```tsx
{member.image ? (
  <Image
    src={member.image}
    alt={member.name}
    fill
    className="object-cover"
  />
) : (
  <div className="aspect-[3/4] w-full bg-bp-blue-light" />
)}
```

<Callout type="info">
The image div needs `position: relative` on the parent for `fill` layout to work. Add `relative` to the photo container div.
</Callout>

## The car (`data/car.ts`, `data/projects.ts`)

The Robots page is about ARC v1, and its facts come from `systems/`, the source of truth:

- `data/car.ts`: the four computers and how they connect (`software/architecture.md`), the sensors (`bom/electrical.md`), and where v1.0 and v1.1 differ (`builds.md`, ADR-0046).
- `data/projects.ts`: the subsystems listed under "Read the whole car", each with a link to its folder in the repo.

When a decision in `systems/` changes one of these, update the file here to match. Don't put a value on the site that `systems/` doesn't have.

## Sponsors (`data/sponsors.ts`)

The list matches the last slide of the club's latest KEFC deck (Drive: *ARC KEFC Fall 2026 - Slides*): Altium, Notion, KEFC and Carleton's Faculty of Engineering and Design. The logos in `public/sponsors/` are cut from that slide, white on transparent.

```ts
{ name: 'Altium', logo: '/sponsors/altium.png', width: 162, height: 36 },
```

`width` and `height` are the logo file's pixel size. Logos keep their sizes relative to each other: the tallest (65px) shows at 2.75rem, the rest in proportion. For a new sponsor, add a white-on-transparent PNG cut at the same scale as the others (or from the next deck's sponsor slide) and a row here. Sponsor tiers and details stay off the site.

## Governance (`data/governance.ts`)

The Governance page paraphrases the current constitution (Drive: *ARC CONSTITUTION W26 v1*): its purpose, membership, the executive (the President, three VPs, the Design Leads and Junior Technical Leads), how the year runs, and elections. The constitution is the authority, so update this file when it's amended.

Its Documents section links the constitution and the folder of weekly meeting minutes in the shared drive (`CONSTITUTION_URL` and `MINUTES_URL` in `data/social.ts`), with an email fallback.

<Callout type="warn" title="Share settings">
Visitors outside the club can only open these if each is set to "Anyone with the link can view" in Drive. Otherwise they get a request-access page.
</Callout>

## Links (`data/social.ts`)

Every external link the site uses (Instagram, Discord, GitHub, email, docs, the Drive documents) and the Behold feed ID are constants in `data/social.ts`. The pages read them from there, so a link changes in one place. `SOCIAL_LINKS` is the list shown in the footer and the contact page's "Follow us" row; each entry names its icon.

LinkedIn is left out until the club has a page: set `LINKEDIN_URL` and add it to `SOCIAL_LINKS` then (Simple Icons has no LinkedIn logo, so it needs one of its own).

## Icons

Service logos come from [Simple Icons](https://simpleicons.org) through `components/ui/BrandIcon.tsx` (`<BrandIcon brand="discord" />`: `discord`, `instagram`, `github`, `drive`), one colour, so they take the surrounding text colour. Generic icons (mail, map pin, book) come from [Lucide](https://lucide.dev) (`lucide-react`). Use an icon where a link goes to a service or does something specific, not as decoration.
